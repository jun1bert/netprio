# Workflow usability

Assessment, asset, master-data and AHP forms warn before leaving a page with unsaved edits. Reverting fields to their original values clears the warning. Valid submissions use the existing loading/submission guard; a pending completion confirmation does not suppress protection. Browser history restoration resets completed submission state. Browser-native leave-page prompts require user interaction and use browser-controlled wording. This is protection against accidental navigation, not autosave or offline storage of assessments.

New assessments offer a search field alongside the native asset selector. Search covers asset code, name and location. Filtering retains the selected asset even when it does not match the search, announces match counts and supports keyboard/native select navigation. Without JavaScript the complete native selector remains usable. Retired assets remain excluded and server-side validation is unchanged.

The inventory includes assessment queue shortcuts and separate filters for not-started eligible assets, unfinished drafts and overdue completed evidence. Existing missing/due and missing-current-scores filters remain available. Continue-draft actions use assessment update policies; reassessment/start actions require creation permission. Retired assets do not receive assessment actions. Existing unassessed-filter semantics remain unchanged.

Applied GET filters and sorting are remembered per authenticated user and list path in browser session storage. Return links and navigation restore the remembered query. Opening an unfiltered list also offers an explicit restore link. Reset clears that list's saved filters. The feature does not store assessment values or passwords; blocked browser storage leaves normal navigation available. The server remains responsible for validating and authorizing every request.

The Compare runs action opens a comparison of two completed saved runs. It matches results by asset record ID and shows preserved ranks, scores, priority levels, rank movement and score differences. Missing participants are marked as not comparable. Warnings explain differences in criteria/directions/weights, priority thresholds, selected scope or ranked membership, and calculation versions. Users can select either chronological order; labels explicitly describe the review run relative to its baseline. Demo provenance is shown for both runs. Neither snapshot is recalculated or modified, and existing ranking-view authorization applies.

Verification covers queue categories, draft permissions, comparison deltas, mismatched scopes/policies/criteria, invalid/draft selections and read-only history. Browser checks cover unsaved changes, reversions, asset selection retention, existing keyboard/focus safeguards, printed explanations, and reflow at a CSS viewport equivalent to 200% zoom. This is not an exhaustive screen-reader or cross-browser accessibility certification.
